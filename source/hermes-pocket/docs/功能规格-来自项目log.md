## 模块 M1：渲染与界面架构

### F-UI-1 长文本滚动 + 一键到底 + 缓存上限　（log 第 1 条）

- **原话**：对于长文本，可能无法向下移动文本，往下拉。也可以一键往下拉，可以限制缓存存储文本长度。
- **载体**：终端视图本身（`#panner` / `#termhost`）+ 顶栏或长按菜单里的一个动作；缓存上限落进「设置」。
- **按键/输入**：滑动到底（手势）、「⤓ 到底」一键、设置项「回滚缓冲（行）」改成**可立即生效 + 显示当前值**。
- **判据**：① TUI（备用屏）里滑一下，`term.buffer.active.viewportY` / tmux 回滚模式可读；② 点「到底」后读到**最后一行可见**（`term.buffer.active.viewportY === baseY`）；
  ③ 设置里把缓冲改成 1000 行后读 `term.options.scrollback === 1000` 且**刷新页面仍生效**。
- **现状（已实现，2026-09-21-uidx-B）**：普通缓冲走 xterm 本地 scrollback（下滑翻开历史 → 出现「⇣ 回到底部（上面还有 N 行）」→ 点它回到最新、入口消失）；
  **备用屏（TUI/tmux）本地没有历史**，滚轮发给远端，并按"往外发了几格滚轮"给「⇣ 回到最新（TUI 里已往上翻 N 格）」，点它**反向发滚轮**把视图还回去；
  长按终端菜单有「⇣ 回到底部 / 最新」；远端没开鼠标时一次会话只问一次「要不要开 tmux 鼠标」，不假滚。
  读数见 `evidence/渲染与设置/F-UI-1-长文本滚动-原始输出.txt`（12 条断言全 true）。

### F-UI-9 字号/设置**真的**生效，且默认保持当前界面　（log 第 9 条）

- **原话**：好像调节字体之类的无效，我需要有效但是默认保持就是当前界面的状态。
- **载体**：设置「字号」输入框（`panels.js:243`）+ 终端上双指缩放 + 长按菜单「⇔ 窗口大小 / 字号」。
- **判据**：改字号 → 读 `term.options.fontSize` 与 `getComputedStyle(.xterm-rows).fontSize` **同时**变成新值，
  且改完不刷新页面、终端列数按新字号重排（`term.cols` 变化可读）。
- **现状（已修，2026-09-21-uidx-A/B）**：根因是**两份状态**（面板 `Panels.prefs` vs 终端 `App.prefs`）+ `boot()` **先读偏好后建通道**
  → 冷启动读不到偏好、改完当场不生效。现在写只走 `App.setPref()`，面板只做只读转发，
  `boot()` 先 `connectTransport()` 再 `loadPrefs()`，捏合缩放结束落盘，设置页有「生效中：字号 … · 回滚 … 行 · 已保存」回读。
  读数见 `evidence/渲染与设置/F-UI-9-设置生效-原始输出.txt`（11 条断言全 true）。

### F-UI-7 左侧隐藏栏（抽屉）　（log 第 7 条）

- **原话**：将多个功能隐藏在左侧隐藏栏内，点击「三」就可以显示左侧隐藏栏，然后可以选择栏目。
- **载体**：`#overlay` 面板（现在顶栏居中 4 个页签：主机/密钥/设置/Hermes）→ 改成**左侧抽屉**：分区 ▸ 栏目，栏目点开进正文区。
- **按键/输入**：`☰`（已有）开合抽屉；抽屉里一行一个栏目（点行进入）；返回靠左缘滑动或「‹」。
- **判据**：读 DOM —— 抽屉打开后 `#drawer` 可见、栏目条目数 = 登记表条目数（**由登记表生成，不是手写**）；
  点条目后正文区 `data-board` 等于该栏目 id；抽屉里的功能数与「功能地图」登记数一致。
- **现状（已实现，2026-09-21-uidx-C）**：`assets/ui/registry.js` 是**功能登记表**（10 项：id/名称/集合/载体/入口/稳定标识/状态/对应测试），
  `#drawer`（左侧滑入的抽屉，点「☰」打开）里的栏目**由登记表生成**，抬头显示当前栏目；`assets/ui/ui.js` 是新的渲染器层
  （`HP.UI.row/list/sheet/status`，两行制行规范与"右列数值不许截断"只在这一个文件里定）。
  没做的栏目（status=planned）**不摆进抽屉**，避免"点不动的空块"，只由 `HP.Registry.check()` 点名
  （`没归属 / 空集合 / 界面空集合 / 没挂上 / 没测 / 未做` 六类缺口）。
  读数见 `evidence/渲染与设置/F-UI-7-左侧隐藏栏-原始输出.txt`。

### F-UI-11 加载完 skill 到出聊天界面之间的长时间停顿　（log 第 11 条）

- **原话**：不知道为什么加载完 skill 之后还需要加载很久的时间才加载聊天界面。
- **载体**：启动路径（`App.boot()`）+ Hermes 页读取（`panels.js:311 renderHermes`）。
- **判据**：打点读时间 —— 启动到终端可输入的 ms、`hermes.info` 回包 ms、Hermes 页首次渲染 ms；
  三项都要有读数，并按「0.1/1/10 秒」三态给用户反馈（骨架/进度/可取消）。
- **现状（已修，2026-09-21-uidx-D）**：启动各阶段有打点（`HP.BOOT`：开始 / 通道就绪 / 偏好就绪 / 字体就绪 / **终端可显示** / 面板就绪，实测 103ms 时终端已可显示）；
  远端读取不在启动路径上；Hermes 页同一次读取只发一遍（`_fetchHermes` 记 promise）+ 60 秒缓存 + 超时 12s/10s + 抬头显示读取耗时。
  读数见 `evidence/渲染与设置/F-UI-11-启动时间线-原始输出.txt`（7 条断言全 true）。

## 模块 M2：会话与流程

### F-SESS-6 启动即挑 tmux + 会话清单与在线状态 + 选择会话（**永不杀 tmux**）　（log 第 6 条）

- **原话**：可以知道 session 和在线状态，可以选择对于 session 会话，当然要选择指令，都在一个 tmux 中，且保持运行中的 session 还在运行。
  启动该软件，如果有某个 tmux 就不管且选择这个 tmux，如果没有 tmux 就创建 tmux，但是**始终不终止 tmux**。
- **载体**：连接后自动执行的「启动流程」（现在是一条 `startCmd` 字符串）+ 一个会话面板（列表行：会话名 / 窗口数 / 是否 attach 中 / 最近活动）。
- **按键/输入**：面板里点一行 = attach 到该会话；「新建会话」一个键；**没有任何 kill/退出键**（这是硬要求）。
- **判据**：① 远端**已存在** tmux 时连上后读 `tmux ls` 输出与 `tmux display -p '#{session_name}'`：会话名不变、**PID 不变**（证明没重建、没杀）；
  ② 远端**没有** tmux 时连上后 `tmux ls` 出现且只有用户选的会话；③ 断开 App 再连，同一 tmux 仍存在（`tmux ls` 一致）且能 attach 回原样。
- **现状（已实现，2026-09-21-sess-A）**：原生只读 op `tmux.list`（跑 `tmux list-sessions -F …` 只回原始文本）→
  `assets/ui/sessions.js` 里 `parse()` 解析 + `bootstrap()` 启动流程（**有会话→attach，不新建不重启；没有→按主机启动命令建；
  再没有→自建 `tmux new -As hermes 'hermes --tui'`**）；首连与断线重连走**同一条流程**；
  新「会话」栏目：状态一行字（在线 / 远端 tmux 几个会话）+ 一会话一行（名字、窗口数、建了多久、最后活动、attach 中·空闲），
  **点行就切过去**；代码里**没有任何 kill 路径**（有源码 grep 自检）。
  读数见 `evidence/会话与流程/F-SESS-6-会话流程-原始输出.txt`（12 条断言全 true）。

### F-SESS-12 监听聊天输出，识别「结束 / 压缩中 / 运行中」（log 第 12 条）

- **原话**：该软件完全可以监听聊天界面的输出，识别是否结束，是否在压缩，是否在运行等等状态。
- **载体**：顶栏状态（一行字）+ 通知；数据来自终端输出流的**单点解析器**（`HP.TuiWatcher` 已在做 alt/busy/title）。
- **判据**：喂真实/回放输出，断言状态机迁移序列（例：`运行中 → 压缩中 → 运行中 → 空闲`），并把**每一段的证据行**打出来；
  状态错判要能打印「为什么」（命中哪条规则）。
- **现状（已修，2026-09-21-sess-B）**：新 `assets/ui/chatstate.js` —— **规则表**（每条规则带"依据文案 + 出处"）+
  状态机：`feed(真实渲染文本)` 判状态、`tick()` 用静默时长判"已结束"、`explain()` 打印"凭什么这么判"（规则 id + 依据 + 命中片段 + 静默秒数）。
  接进 `renderChunk`（**唯一输入**）与每秒 tick；顶栏一行字显示「模式 · 状态」；后台从"在跑/在压"掉到"已结束"推一条通知（设置项 `notifyChatState`）。
  规则文案取自本机 Hermes TUI 产物 `ui-tui/dist`（`Ctrl+C to interrupt…` / `Thinking` / `~N tokens` / `compacting` / `compacted` /
  `Compressions: N` / `[interrupted]`），grep 原文见 `evidence/会话与流程/规则依据-来自Hermes源码.txt`；
  读数见 `evidence/会话与流程/F-SESS-12-聊天状态机-原始输出.txt`（15 条断言全 true）。
  **待真机校准**：真 Hermes 压缩上下文时终端里到底打印哪一行；若与 dist 里的词不同，改规则表一行即可。

### F-SESS-10 「连接总是说新建立连接」+ 是否每次都上传 key（log 第 10 条）

- **原话**：连接总是说新建立连接，是每次都会上传 key 还是什么原因导致的这个问题。
- **载体**：连接过程的一次性提示（`writeHint` / `confirm` 弹窗 / 系统通知）。
- **判据**：连同一台**已信任**的主机 N 次（N≥3），**记下每次弹出的提示与次数**：
  期望「首次信任」只出现 1 次；`hostkey` 事件里 `known=true` / `newType=false` 可读。
- **现状（已修，2026-09-21-sess-C）**：TOFU 已持久化（`Ssh.kt` 的 `tofuKeyRepo` + `Store.knownFingerprint`，target 用 `host:port`，与写入一致），
  但**提醒写错了位置**：`onHostKey()` 开头那句「首次连接，需要确认主机指纹」**每次连接都发**（已知主机、指纹一致也发）
  —— 实测修复前已信任主机一栏 `app.notify=1`，修复后 `=0`；提醒现在只放在真要人决定的分支，
  已知主机一致时连提醒都不发（`console.log('[hostkey] 已知主机 · 指纹一致 · 无需确认')` 留痕）。
  「每次连接都弹『通道就绪』」也顺手改成**本次运行只说一次**。
  「是不是每次都上传 key」的答案：**不是** —— 只有主机还记着"用密码登录"时第一次连接调 1 次 `key.install`，
  装好并验证通过后主机切成密钥登录，第二次连接不再调（实测 1 → 0）。
  读数见 `evidence/会话与流程/F-SESS-10-连接提示与公钥-原始输出.txt`（含修复前对照）。

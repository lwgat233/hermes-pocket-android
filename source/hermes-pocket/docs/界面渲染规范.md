# 界面渲染规范（Pocket 版 · 沿用 cdp 学来的那套）

来源：`/vol1/1000/airesults/cdp/docs/{界面规范-列表行.md, 开发与界面指导.md, 界面模块化.md}` +
技能 `project-method-and-ui-doctrine`（§6 §9）+ `android ▸ references/webview-ui-pitfalls.md`。
**Pocket 的界面是 WebView（HTML/CSS/JS），所以这些规矩直接是代码规矩。**

## 1. 一份数据只有一个权威源

- 现状隐患：设置项的值存在**两处** —— 原生 `pref.*` 与 `localStorage['hp.'+k]`（`panels.js:462` 的 `catch` 里写 localStorage），
  界面读 `Panels.prefs`、终端读 `App.prefs`。**改一处另一处不知道**，这就是「调了字号像没生效」这类现象的温床。
- 规矩：**能力层（Kotlin/RPC）→ op 层（`host.*` / `key.*` / `pref.*` / `hermes.*`）→ 渲染器层（`HP.UI.*`）→ 界面层（板块装配）**，
  只允许上层调下层；界面**不许**自己拼 HTML 字符串读第二份状态。

## 2. 一个东西只有一个渲染入口

- 现状：列表/卡片 HTML 散在 `panels.js`（`renderHosts` / `renderKeys` / `_hermesHtml` / `renderSettings`）和 `app.js`（流量小窗、对话框）里，
  各自 `innerHTML` 拼。**同一种东西长得不一样**的风险已经出现（cdp 那边踩过：同一个列表两处渲染，改一处另一处不动）。
- 规矩：新增 `HP.UI`（渲染器层）：
  - `UI.row({title, sub, right, fields, actions, onTap})` —— **两行制行**（左列大标题/小灰次行，右列固定列）；
  - `UI.sheet({title, fields, actions})` —— 点行弹出的小窗（键小字在上、值大字在下、每对一条横线、底部一组〔取消〕〔确定〕）；
  - `UI.list(rows, {empty})` —— 列表 + 空态一句；
  - `UI.status(text)` —— 状态一律**一行字**。
  老代码不必一次全改：**新加的板块必须走 `HP.UI`**，改到的文件顺手搬过去。

## 3. 列表行 = 两行制（硬规则，照 cdp 那份）

1. 标题大字号：≥ 14px、字重 600、占第一行。
2. 次行（网址/次要信息）小字号：≤ 12px 灰、占第二行。
3. **右列固定、数值完整**：`flex: 0 0 auto; white-space: nowrap`，**不许 `text-overflow: ellipsis`**；
   数字用 `font-variant-numeric: tabular-nums`。宁可标题被截，也不许把数截掉。
4. 只有标题（与次行）才用「…」：`overflow:hidden; text-overflow:ellipsis; white-space:nowrap`，左列 `flex:1 1 auto; min-width:0`。
5. 行高按内容（`min-height: 44px`），不写死把第二行切掉。

## 4. 界面不臃肿（用户反复强调）

- 一屏只回答一个「我要干什么」：上面控件、下面结果；同一件事不摆两遍。
- **常驻按键 ≤ 3 个**，第 4 个起收进「更多」或抽屉。
- **行里不摆 `⋯`**，不给「可展开」暗示；要操作就点开那一行。
- **界面里不写说明文字**（`hint` 现在很多 —— 设置页那堆 hint 要收进「?」或文档）；界面只写「干什么」，不解释「为什么」。
- 状态用**一行字**，不要用一排按钮表达状态。
- 空态只有一句「下一步怎么做」，而且真的能照做。
- 术语一致：叫「会话」就全界面叫「会话」，别一会儿「session」一会儿「会话」。

## 5. 功能一多就按「登记表 → 归类 → 抽屉」来（log 第 7 条的落地方式）

1. 先**扁平登记**一张表：功能 id / 名称 / 载体 / 入口 / 稳定标识 / 状态（放 `assets/ui/registry.js`，由 JS 直接引用）。
2. 归到 **5~7 个集合**，一个功能只属于一个集合；跨集合只放跳转入口。
3. 载体按粒度选：大功能独占一屏；中功能折叠块（一行摘要）；小功能＝行 + 点行小窗；状态＝一行字。
4. 入口两级：**集合 ▸ 栏目（左侧抽屉）**，再加搜索直达。
5. 抽屉与板块**由登记表生成**，自检能报「哪个功能没归属 / 没挂上」。

## 6. 渲染相关的硬指标（可读回来）

| 指标 | 数 | 怎么读 |
|---|---|---|
| 交互反馈 | < 400 ms | 点下去到 DOM 变色/文字变的耗时打点 |
| 三态阈值 | 0.1 / 1 / 10 s | 加载态：无提示 / 骨架 / 必须进度 + 可取消 |
| 触控目标 | ≥ 48dp（WebView 里约 48 CSS px） | `getBoundingClientRect()` 读宽高 |
| 文本对比 | ≥ 4.5:1 | 读 `color` 与背景算比值 |
| 字号生效 | 立即 | `term.options.fontSize` 与 `getComputedStyle(.xterm-rows).fontSize` 双读一致 |

## 7. 自检问句（每轮问一遍）

- 第一次用的人，能不能不看说明就点对？
- 加同一个类的新功能，要不要改渲染层？要改就是抽象错了。
- 这个列表/小窗，是不是**同一份数据、同一个渲染入口**？
- 界面上还有没有「登记了没做」「没有交互」「没有测试」的空块？

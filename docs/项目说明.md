## 四条缺陷的处理结论

| # | 你报的问题 | 结论 |
|---|---|---|
| 1 | 随便按哪都弹键盘 | 已修：单击不再抢焦点，改用显式「⌨ 键盘」按钮 |
| 2 | 密钥无法生成 | 已修：三层问题（Android 多版本 JAR + jsch 不支持导出 EdDSA + 需自己拼 OpenSSH v1）。三种算法都能生成，且**用真 OpenSSH 验证过能登录** |
| 3 | 输入后被过快刷新掉 | 已修：未连接不再吞草稿；面板重绘不再清掉正在填的表单 |
| 4 | tmux 滚轮 | 之前**没做通**，现已补齐（含一键开 tmux 鼠标 + 不依赖鼠标的回滚键） |
| 5 | 点主机菜单的「连接/删除」没反应 | 已修：菜单被 `pointerdown` 提前关掉，click 落不到按钮上（已用 A/B 对照坐实） |
| 6 | 长按弹出的选项也没用 | 同 5，一个根因 |
| 7 | 连接后输入时 Esc 等键位被隐藏 | 已修：键条原是横向滚动条（28 键只见 8，且被 focus 卷走后 Esc 整排出屏）。改成 8 列网格铺满，主键 16 个全可见 |
| 8 | 键盘弹出时键条不跟随、有等待感 | 已修：`visualViewport` 每帧只改 CSS 变量（0ms 跟上），昂贵的 `term.resize` 单独防抖。A/B：偏差 0px/0 帧 vs 旧 80px/18 帧 |
| 9 | SSH 窗口大小只能选固定档位、太小 | 已修：新增「⇔ 窗口大小 / 字号」对话框，列数 20–400、行数任意（0=跟屏幕）、字号 6–32 任意值。远端 `stty size` 回读确认 PTY 真的跟着变 |
| 10 | 每次连接都说「指纹发生变更」 | 已修：`known_hosts` 改为按 (主机, 密钥类型) 分别记录（同真实 SSH）。旧记录自动迁移；同类型指纹一致时**完全不弹框**；换类型只是平静提示；同类型换了密钥才报警。加「忘掉本机指纹」逃生口 |
| 11 | 窗口比屏幕还宽（左右超出） | 已修：默认**按屏幕宽度铺满**（真 TUI 下 48×33/13px、不超出屏幕），不再为凑 80 列把终端撑宽、把字缩到 10px。「TUI 保真」变成默认关闭的显式开关；超出时顶栏显示 `⟷`；对话框显示「屏幕可容纳 N 列」+ 超宽警告 +「适配屏幕宽度」一键填 |
| 12 | 我需要大字号（Termux 没这问题） | 已修：字号上限 24→**48**（设置面板/对话框/双指缩放统一用 `minFont=6 / maxFont=48`）；并修掉「最少 20 列」的下限夹取——它会在字号调大时把列数抬高、重新撑宽屏幕。字号 13→48 逐档实测：列数 48→13，每一档都不超出屏幕，远端 `stty size` 同步 |
| 13 | 推荐键位有时候还是消失 | 已修：顶栏 40 + 输入框 145 + 键条 97 = 282px 超过键盘弹起后的可视高度，键条被整体挤出屏幕。新增 `fitChrome()`：空间不够时**键条和终端优先**，输入框先压低、实在不够自动收起。实测视口 377/300/240/200 下键条**全部完整可见** |
| 14 | 界面不跟着 SSH 刷新 | 已修，两个成因：① 我在 `onPause` 里调了 `web.onPause()`，只要有系统窗口（如权限弹窗）盖上来，WebView 就冻住（实测 rAF 0 帧、定时器 0 次）→ 改成**绝不暂停 WebView**；② `visualViewport` 变了却可能不发 resize 事件（实测一个事件都没有）→ 加每帧只读两个数字的**看门狗**。另加原生 512KB 环形缓冲 + `session.since(seq)`，回前台补回冻结期间漏掉的输出（实测补回 200 字节且不重复刷） |
| 15 | 能不能自动把公钥复制到服务器 | 已做：连接成功后自动 `ssh-copy-id`（幂等 + 权限摆正），**并用密钥真连一次验证**，验证通过才切成密钥登录（否则可能再也连不进去）。端到端实测 `verified=true`、服务器 `authorized_keys` 就是刚装的那把、切密钥后重连成功 |
| 16 | 不能用单指向上滑查看上面的文本 | 已修：单指拖动原来是按「横滑/鼠标拖动」处理，**竖向也不滚动**；滚动被绑成双指滑（太隐蔽）。改成**单指竖向滑 = 翻历史**（Termux 一致），横向才平移/发鼠标；并加「⇣ 回到底部（上面还有 N 行）」胶囊 |
| 17 | **下拉还是看不到上面的文本** | 已修，三个成因：① `#toast` 没设 `pointer-events:none`，浮在终端上吃掉手势；② `#stage` 没声明 `touch-action`，浏览器自行仲裁手势；③ **TUI 里本地根本没历史**（备用屏不存 scrollback）—— 这条最可能是你遇到的。现在 TUI 里下拉会**弹一键开 tmux 鼠标**：实测点完 `鼠标模式 0→1002`、顶栏从「TUI·滚动受限」变「TUI·鼠标」、再下拉发出 13 个滚轮序列。**上一轮的验证是假的**（用合成 PointerEvent，绕过了手势仲裁），这轮全部改用真实触摸注入 |
| 18 | **「发送」那一栏不实时** | 已修：输入框原来是"攒着"的，敲完点「发送」才整行进终端。现在改成**按键直通管**（和点键条同一条链路）：逐键 `keydown` 直发（回车/退格/Tab/Esc/方向键/可打印字符 + Ctrl·Alt 锁定一起套用），输入法上屏与粘贴走 `input` 一起送。实测敲 `l`→发 `["l"]`、敲 `s`→发 `["l","s"]`、中文上屏→发 `["l","s","中文测试"]`，输入框全程为空。想回到攒着模式：输入框左边「实时 / 攒着」开关（或设置里 `liveComposer`） |
| 19 | **输入 ctrl+b d 退不出 tmux** | 已修，两个成因：① **TUI 行的键条里压根没有 Ctrl/Alt**（只在 shell 行和「⌄更多」里，TUI 下按不到）→ 已把 Ctrl/Alt 挪进 TUI 可见行；② **键盘输入不看 Ctrl 锁定**（`term.onData` 一把梭）→ 点 Ctrl 再敲 b 发出去的是普通 `b`，且 Ctrl 一直亮着不消。实测：点 Ctrl → `锁定Ctrl=true`、敲 b → 发出 `C-b`、敲 d → **tmux 客户端列表清空（已脱离）、会话仍在（只是 detach）** |
| 20 | **点发送之后终端要等一会儿才更新** | 已修：先量管道本身（发出→收到 4.5-10.3ms、解析 1.3-2.2ms、绘制 10.7-11.7ms，**共 16-24ms＝一帧**，渲染不慢）；再量发送前后的时间线，抓到 `resetGeometry()` **无条件**发 `session.resize` —— 点一次发送连发 3 次 48×33（尺寸根本没变）。远端每收一次窗口变化就 SIGWINCH → TUI **整屏重画**，连发 3 次＝重画 3 次。加 `pushResize()` 按（会话,列,行）去重，**实测 resize 次数 3 → 1** |
| 21 | **按了 Esc 之类的键，键盘会结束** | 已修：功能键是 `<button>`，点它会把焦点从输入框抢走、输入法随之收起。改法三步：① `pointerdown` 上 `preventDefault` 拦掉焦点转移；② **动作改由 `pointerup` 触发**（实测被 preventDefault 的 pointerdown 会连带吞掉 `click`，只挂 click 会"按了没反应"）；③ 动作后把焦点**还给按之前正在输入的那一处**（在输入框里点 Esc 就留在输入框）。实测：点 Esc 发出 `0x1b` 且焦点仍是 TEXTAREA。**顺带修两个真 bug**：`⌄更多` 展开瞬间残留 click 会漏发一个杂散键（0x0）→ 加 350ms 吞掉窗口；**输入框里锁定 Ctrl 后打字母不带修饰键**（手机字母多走输入法"提交"的 `input` 事件而非 keydown）→ 抽出统一 `sendLive()`，实测点 Ctrl 再敲 x 发出 `0x18` |
| 22 | （工具）cdp.mjs 的 `tap` 传坐标时静默跳过 | 已修：`tap` 以前只认选择器，传坐标对象时记一条"元素不可见"就继续跑，**不点击也不报错** —— 导致"真实点击"白排查好几轮。现在支持坐标写法，目标不可见时直接抛错 |

## 新增功能：终端事件通知

「丢下手机去干别的」和「出事了人不在旁边」这两件事，本质都是**需要主动叫到人**。所以做了原生通知：

| 触发 | 怎么来的 |
|---|---|
| **命令跑完了** | 按回车起算，输出静下来且回到提示符就认为跑完（只通知 ≥10 秒的；**远端零配置**） |
| 命令跑完了（精确） | 远端装了 shell 集成时用 `OSC 133;D;<退出码>` |
| **远端响铃** | `BEL` —— 很多程序跑完/出错都响铃 |
| **脚本主动通知** | `printf '\e]777;notify;标题;正文\a'`（OSC 777/9，iTerm2/kitty 那套协议） |
| **需要授权 / 连接失败** | 主机指纹确认、认证失败、没保存密码 |

- **前台不打扰**：正看着屏幕时普通事件不弹通知，只有「需要授权」类会穿透
- 同类事件节流，避免被刷屏；点通知回到 App 并滚到底部
- 每种触发在设置里都能单独关

实测（切后台模拟"手机放桌上"）通知栏收到：`命令已完成（15 秒）`、`构建完成 / 用了 42 秒，3 个警告`、`终端响铃`、`首次连接，需要确认主机指纹`；前台下普通事件 `posted=false`、紧急事件 `posted=true`。

另外还揪出一个你报告之外的**会让功能彻底哑掉的真 bug**：协议里关联 id 与业务 id 撞名，导致 `key.reveal`/`key.delete`/`host.delete` 永远超时 —— 详见缺陷修复报告。

## 新增功能：流量统计（下行 / 上行）

顶栏一格 `↓ 981.9K` 实时显示**下行**（远端发来的）流量；点开看详情：下行速率/峰值、上行、
平均下行、会话时长、数据块次数、**服务端 socket 计数**、**差额（补发等）**、跨会话累计下行，带「计数归零」。
长按终端菜单里也有一项「📊 流量统计」。

两份计数互相印证：渲染侧（JS，实际送进终端渲染的字节）与 socket 侧（原生，网线上真实收发的字节）——
差额正好用来看"回前台补发"补了多少。**实测用已知大小核对**：拉 1,000,000 字节 → 统计 1,000,095
（多出的 95B 正是命令回显+提示符）；发 5,002 字节 → 统计**正好 5,002**。
顺带修掉顶栏把下行标成 `↑` 的方向错误。

## 新增功能：文件事件通道（另开一条 SSH + 手机系统通知）

服务端 home 下放一个**只追加 + 限额**的文件，我往里写一行，**手机就调起系统通知**。
手机端会**另开一条独立 SSH 连接**（`tail -F`）盯着它 —— 终端会话重连/断开都不影响通知。

```
auth: 需要你点一下确认 | 远端在等你输入 sudo 密码     ← 需要授权（紧急，前台也穿透）
done: 构建完成 | hermes-pocket 调试包已生成          ← 做完了
info: 顺便说一句                                     ← 普通
```

写的时候用服务端的 `~/hpk-notify.sh <kind> <标题> [正文]`（负责只追加 + 超限裁掉最老的整行）；
协议与排障见 `~/HERMES-POCKET-EVENTS.md`。App 里：设置 →「事件文件路径」有实时通道状态，长按终端也有「📡 事件通道」。

实测：连接后到 `:2222` 的 SSH 连接变成 **2 条**（终端 + 事件通道），关掉开关回到 1 条；
三种事件都在通知栏拿到真实 `android.title/android.text`；格式写错的行也不丢（整行当标题）；
前台下紧急事件 `posted=true` 穿透、普通事件 `posted=false` 不打扰；事件推送期间终端照常可用。

## 新增功能：省电板块（省电，但尽量不断连）

设置里新增「省电」：模式（关 / **息屏时省电（默认）** / 后台+息屏省电）、息屏后延迟多久进入省电，外加
「立刻省电一次 / 立刻退出省电 / 刷新状态」三个按钮，以及一行实时状态（省电中? 唤醒锁持有/已释放 · 屏幕亮/灭 · 前台/后台）。

**核心取舍：省电 ≠ 断连。** 待机耗电大头是①一直握着 CPU 唤醒锁 ②每秒/每 20 秒的定时器反复把 CPU 拽醒
（睡着时的重连风暴更费）。所以省电只停"我们自己花 CPU 的活"：释放唤醒锁、取消渲染看门狗、
停掉每秒统计与 App 层心跳 —— **TCP 连接由内核留着**，亮屏回来立刻补上漏掉的输出。

**省电期间怎么保存输出（第二轮改对的）**

- **后台真的不渲染**：原生层**直接不发** `data` 事件，数据只进内存环形缓冲（512KB）+ **追加落盘**
  （`files/spill-<会话id>.log`，1MB）；前端后台期间一个字节都不碰。
- **心跳不能关，要拉长**：省电期间 SSH 心跳 `30s → 120s`。关掉（0）会被 NAT/移动网络当成死连接回收，
  "省电"把连接省没了 —— 与「连接不要断开」直接冲突。
- **回前台再渲染**：顺序是「先攒住新事件 → 取走落盘缓存 → 关省电 → 按顺序补渲染 → 放行攒下的事件」，
  顺序错了会把新数据插到旧数据前面。

实测（原生 + 服务端双证据）：
```
前台    省电=false · 唤醒锁=持有(PARTIAL_WAKE_LOCK 'hermes-pocket:ssh') · 定时器全在 · 连接 2 条
切后台  省电=true  · wakeHeld=false（已释放）· 定时器全停 · 心跳=120s · **连接仍是 2 条（没断）**
后台中  远端输出 2000 行 → 渲染水位仍是 6、终端行数仍是 32（一个字节没渲染）
                        落盘 spill-*.log = 28114 字节（数据在硬盘上）· 连接仍是 2 条
回前台  渲染水位 6→67、终端行数 32→2002（补渲染出来了）· 落盘缓存已取走清空 · 连接仍是 2 条
息屏    息屏→save=true/interactive=false/唤醒锁释放；唤醒→全部收回
```

**真断线也能自己回来**（专门验「重连要能拿到之前没获得的信息」）：
掐掉服务端该连接的 sshd 会话进程 → 3 秒内状态变 `reconnecting` → 6~10 秒自己连回来（连接数恢复 2 条）
→ 断线前的输出仍在终端里（会话对象不销毁，环形缓冲跨重连保住）→ 重跑主机配的启动命令，
用户回到原来的会话（配 tmux 就回到 tmux）。开关：设置 → 省电 →「重连后自动回到原会话」（默认开）。

诚实说明：页面隐藏时 Chromium 本就会暂停 rAF，所以"取消看门狗"省得有限；真正省电的是**释放唤醒锁**、
**停掉 setInterval**、**后台不渲染**这三条。

## 新增功能：在手机上看 Hermes 的技能与记忆

面板第 4 个标签页「Hermes」：

- **记忆**：`USER.md`（关于你）+ `MEMORY.md`（我的笔记）全文，带占用比例（上限从远端 config.yaml 读，实测 2200 / 1375）和条目数（`§` 分隔，实测 8 条）。
- **技能**：按目录分类列出全部技能（实测 62 个 / 12 类），带 description、路径、字节数；**点开看 SKILL.md 全文**，可一键「在终端打开」（`less`，按 q 退出）。
- 只有真停在这一页才去读远端，打开面板不会白拉 60 个文件。

取数复用终端那条会话开临时 exec 通道（带超时），不新开连接；命令是固定字符串，读文件走严格路径校验。

顺带修掉两个真问题：① **分隔符被吞** —— 记忆文件末尾没有换行，`echo @@MEM` 粘在正文尾巴上导致标记失配，MEMORY 的内容被整段并进 USER（显示 127% 而 MEMORY 为空）；② **Kotlin 块注释可嵌套** —— 注释里写"斜杠+星号"的通配路径会开启嵌套注释，把文件后半段吃掉，报错是完全误导人的 `Unclosed comment`。

## 通知收不到？先看通知权限（已做成看得见的）

系统的行为是：**没有通知权限就把通知静默丢掉**（不报错、不提示），所以"没收到"没有任何线索。
现在 App 里有三个入口：

1. **连上之后自动自检**：没权限会弹框说明白，点「去授权」直接拉起系统权限弹窗。
2. **设置 →「通知权限」卡片**：实时状态（已授权/未授权 + 前台/后台）+ `申请通知权限` / `打开系统通知设置` / `发一条测试通知` 三个按钮。
3. **长按终端 →「🔔 通知自检（权限 / 测试通知）」**。

另外两条容易误判的规则：

- **App 在前台时，普通通知不发**（你正看着屏幕，弹通知是噪音）。现在会**改成应用内浮一条**，
  不再是"什么都不发生"。真正紧急的 `auth` 类前台也照弹。
- **国产系统（MIUI/EMUI/ColorOS…）** 还要另外在「设置 → 应用 → Hermes Pocket → 通知」里
  允许**通知**、允许**后台弹通知**，有的还要开**自启动**，否则锁屏久了照样收不到。

实测：撤权限冷启动 → 系统弹窗 ✓；取消后连上 App 主动提示 →「去授权」重新拉起弹窗 ✓；
点 Allow → `granted=true`、应用内状态更新、自动自测通知落到通知栏 ✓。

## 测试方法上的一个坑（记在这里免得下次再踩）

CDP 的 `Input.dispatchTouchEvent` **只送 pointer 事件、不合成 click**。用它去测「按钮点得动点不动」，
会得到一片假阴性。必须用 `Input.synthesizeTapGesture`，或者鼠标事件（`Input.dispatchMouseEvent`
的 press/release 会走完整的 `pointerdown → pointerup → click`，顺序和真机轻点一致）。
判断测试工具本身可不可信的办法：先拿一个**已知能用的控件**做对照组。

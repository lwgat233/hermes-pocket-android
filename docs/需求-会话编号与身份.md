# 需求：会话/角色列表每条要**看得出是谁**（编号 + 一行身份）

**来源**：本人 2026-09-24（女仆代转 #1264）——「怎么会有两个我呢？……我不太清楚哪个 session 是指向我？编号是啥？我也不知道编号怎么看」

**问题**：App 里会话/角色条目不显示编号与身份，本人分不清"哪条是自己、哪条是经理、哪条是女仆"。

## 一、要做的（先文档后代码）

1) **每条显示编号**：取 `talk.db` 的 `session.id`（如 `#4`、`#6`、`#11`）；**会话页与信息窗里同一条必须同一个号**。
2) **每条给一行"这是谁"**（一眼分得出，别让人猜）：
   - `#4 女仆（本人通道）` —— App 第二入口；旁注：QQ 通道才是本体/主线
   - `#6 经理` —— 派活/判报告；**不是本人**
   - `#11 调查者` · `#5 测试者` · `#8 渲染者` · `#10 功能创造者`
3) **命名统一**（本人定的叫法，App 文案照这个，别一会儿"女仆"一会儿"maid"）：
   - 角色窗口（都在 `roles` 会话里）：`owner-me` / `pipeline-*` / `home-maid`
   - 女仆的 QQ 通道：**「本人-女仆通道」**（在 `hermes` 会话里）
4) **边界（不许改坏）**：QQ 通道＝女仆本体/主线（本人消息与报告转达仍走 QQ）；App 那条只是**第二入口**；
   **本人只有一个**（署名 `me`），他**不是**角色行、**也不是**经理。

## 二、判据（验收口径，逐条可测）

- 打开 App 的会话页/角色页，**每个条目都能看到 `#id` + 一行身份**，且与信息窗里显示的一致（同号同人）；
- 随便点一条，能一眼说出"这是谁"（不用打开才知道）：`#4 女仆（本人通道）` / `#6 经理` 这类读数**截图或 DOM 原文**留证；
- 编号来源单一：`session.id`（不在前端另造编号）；列表里**不出现同一个窗口两条**（去重）；
- 其它板块（聊天页/设置页/网络页）的布局不被挤坏（照 SPEC §10 分板块复测：主块＝⑤会话页/⑧频道页）。

## 三、流程（照按职责分活）

1) **定位与改法**（author）：显示位（会话页/角色卡/信息窗各在哪几行）、编号怎么取、怎么去重、命名怎么统一；
2) **界面改动与出包**（renderer）：按改法改 + `build.sh` 出包；
3) **复测**（tester）：真机按上面判据逐条量（含"随便点一条能说出是谁"）。

# 这一轮（用户口述，2026-09-21 晚）要修的四件事

原话拆条（用户口语，逐条落到"读回来的判据"上）。这一轮**先复现、再改**，每条都留证据。

## N-1 没连接的时候点「☰」报错
- 原话：「好像我没连接的时候打开那个三，他就会报一个错误，不知道清楚是什么错误。」
- 要复现的：无会话（`sessionId=null`）状态下开抽屉，看**控制台/页面错误**与抽屉渲染结果。
- 判据：① 开抽屉时页面不报错（`console.error` / 未捕获异常为空）；
  ② 抽屉照样打开，条目照常列出（能看主机/密钥/设置，只是连不上而已）；
  ③ 该栏目的远端行（Hermes 那几行）显示"要连上才能读"这类**可读的状态**，不是错误堆栈。

## N-2 点终端那块屏幕还是会弹虚拟键盘
- 原话：「点击这个终端界面，不点击那个输入框和下面的那个键盘，他就会弹出我的虚拟键盘，就莫名其妙。
  这个可能是某些逻辑没有清理掉。」
- 现状：本地台与模拟器都验过"点终端后焦点不落隐藏输入框"（R-15），但**真机上仍然弹**。
- 这一轮的做法（不再只靠"焦点不落它"）：**双保险**
  ① 焦点守卫照旧（谁把焦点塞给终端里的输入元素、而用户没按「⌨ 键盘」，就立刻收回）；
  ② 给隐藏输入框加 `inputmode="none"`（没要键盘时）／`inputmode="text"`（按了「⌨ 键盘」时）——
     即使它被聚焦，系统也不弹软键盘。这是真机路径上最有效的一招。
- 判据：点终端后 `document.activeElement` 不是隐藏输入框 **且** 它的 `inputmode === 'none'`；
  按「⌨ 键盘」后 `inputmode === 'text'` 且焦点在它上面（键盘要能用）。

## N-3 全屏（沉浸）模式要保留输入框
- 原话：「然后全全屏模式也要保留这个输入框。」
- 现状：`body.immersive #topbar, #keybar, #composer { display: none }` —— 输入框被一起藏了。
- 改法：沉浸模式**只藏顶栏与功能键条**，输入框保留；并给沉浸模式一个不占地方的收/放方式
  （否则没顶栏就退不出来 —— 长按菜单/返回键仍在，但用户看不见提示）。
- 判据：进沉浸模式后 `#composer` 的 `display !== 'none'` 且**它在视口内**（矩形高度 > 0、底部不超屏）；
  顶栏与键条仍然藏起来；退出后三者都回来。

## N-4 输入框「攒着」与「实时」的换行语义
- 原话：「然后我觉得这个输入框攒着的话，它不会自动添加换行符。咱这转为实时的话，要把它输出到里面去。
  同样的不添加换行符。」
- 读法（待确认）：① 在「攒着」模式下敲的内容，切到「实时」时应当**把它送进终端**（实时=逐键直通，
  所以把已经攒着的那段当作"刚敲的"发出去）；② **两边都不自动加换行符**（不加 `\r`，因为那是"提交/执行"，
  由用户自己敲回车或点发送决定）。
- 判据：框里放 `echo hi`（攒着）→ 切到实时 → 终端那边收到 `echo hi`（**不带** `\r`）且框里清空；
  反向（实时→攒着）不动内容。
- 待用户确认的点：**「攒着」模式下点「发送」到底要不要自动补 `\r`**（现在的行为是补，等于"发一条命令并回车"）。

## N-5 退出沉浸模式后，「☰」和上下滑动都没反应
- 原话：「不知道是不是哪些原因，就是从全屏状态退出来，嗯这个三没有效果，好像上下滑动也没有效果。」
- 要复现的：进沉浸 → 退出 → ① 点 ☰ 看抽屉开不开、点落在哪个元素上；② 在终端上拖动看滚轮/位移有没有反应。
- 判据：退出沉浸后 ① 点 ☰ 抽屉打开；② 终端上拖动与进入沉浸前**行为一致**（读数相同）。

## 2. 三个功能点

### F-SESS-6 启动挑 tmux / 会话清单 / 选择 / 永不终止（log 第 6 条）— sess-A

- **改法**：只读 op `tmux.list`（原生跑 `tmux list-sessions -F …`，只回原始文本，解析留在界面侧好测）
  + 新 `assets/ui/sessions.js`（`parse()` 纯函数 + `bootstrap()` 启动流程）+ 新「会话」栏目；
  **首连与断线重连走同一条流程**（以前重连无脑重跑启动命令，会在原会话外再建一个）。
- **流程**：远端有 tmux → **attach，不新建不重启**；没有 → 按主机启动命令建；再没有 → 自建 `tmux new -As hermes 'hermes --tui'`。
- **读数**（12 条断言全 true）：解析真实输出 2 个会话；有会话时发出的是 `tmux attach -t 'hermes'` 且**没有** `new -As`；
  没会话时按主机命令/自建；栏目标题与两行会话行、点行切过去；**全程没有任何 kill**（并对源码做 grep 自检：无命中）。

### F-SESS-12 聊天输出状态机（log 第 12 条）— sess-B

- **改法**：新 `assets/ui/chatstate.js` —— **规则表**（每条规则带"依据文案 + 出处"）+ 状态机
  `feed()`（喂真实渲染文本，唯一输入）/ `tick()`（静默判结束）/ `explain()`（打印凭什么这么判）；
  接进 `renderChunk` 与每秒 tick；顶栏一行字「模式 · 状态」；长按终端菜单「ℹ 聊天状态」可查依据；
  后台从"在跑/在压"掉到"已结束"推通知（新设置项 `notifyChatState`）。
- **规则不是猜的**：文案取自本机已装 Hermes TUI 产物 `ui-tui/dist`（`Ctrl+C to interrupt…`/`Thinking`/`~N tokens`/
  `compacting`/`compacted`/`Compressions: N`/`[interrupted]`），grep 原文存 `evidence/会话与流程/规则依据-来自Hermes源码.txt`。
- **读数**（15 条断言全 true）：7 条真实文案逐条判定正确；迁移序列 `运行中→压缩中→运行中→已结束`；
  静默阈值前不算结束；真实链路（传输层推输出 → 顶栏文字变）；explain 打出依据与命中片段；规则覆盖率 7/7。

### F-SESS-10 连接提示 / 是不是每次都上传 key（log 第 10 条）— sess-C

- **用户问的是两件事**，分别用读数回答：
  1. **「连接总是说新建立连接」= 缺陷**：`onHostKey()` 里那句"首次连接，需要确认主机指纹"的提醒
     写在**函数开头**，于是**每次连接**（包括同一台已信任主机、指纹一致）都会推一条通知。
     修复前实测：已信任主机一栏 `app.notify = 1`（弹框 0）；修复后 `app.notify = 0`。
     改法：提醒只放在真要人决定的分支（指纹变了 / 新密钥类型 / 真·首次），已知主机一致时连提醒都不发（留一条日志）。
     顺带把「原生 SSH 通道就绪」这类提示改成**本次运行只说一次**。
  2. **「是不是每次都会上传 key」= 不是**：密码登录的主机第一次连接会调 1 次 `key.install`，
     装好并用密钥验证通过后主机被切成密钥登录，第二次连接**不再调**（实测 1 → 0，且主机登录方式变成 `key`）。
     设置项 hint 也改成直说这条行为（"之后不再装，避免每次连接都上传一遍"）。
- **读数**（7 条断言全 true）：已信任主机静默 / 首次连接会问 / 指纹变了会问 / 新密钥类型会问 /
  第一次会装公钥 / 装完切成密钥登录 / 第二次不再装。

## 4. 测试方法上的进展

- 测试台支持「数 RPC 次数」（`window.__calls`）与「推原生事件」（`window.__push`），
  所以"到底调了几次装公钥""到底弹了几次框"这类问题现在是**数出来的**，不再靠读代码猜。
- 状态类功能的规则必须带**依据与出处**，并把找依据的那次 grep 原文入档（见 M2 报告 §2-F-SESS-12）。

## 5. 没做的 / 缺口（如实说）

1. **设备端复验仍未做**：宿主模拟器 guest 卡死被 kill，恢复要 `docker rm -f notifbridge-emu` + `docker run …`，
   这条命令被安全策略拦下等用户批准（弹窗超时，未重试）。M1、M2 全部结论目前都来自本地 Chromium 测试台。
2. **真机校准项**：Hermes 真压缩上下文时终端打印哪一行；若与 `ui-tui/dist` 里的词不同，改 `chatstate.js` 规则表一行。
3. **登记表还没收状态类功能**：`chat-state`（顶栏那一行字）与 `model/prompt/skills-dl/net` 一样只在文档里，
   没进 `registry.js`；下一轮做 M3 时一起补（登记表要能容 `kind:'status'` 这类"不长在栏目里"的功能）。
4. 若某台主机装公钥始终失败，每次连接仍会重试一次（刻意重试，没做"不再重试"开关）。

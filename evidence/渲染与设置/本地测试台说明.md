# 本地测试台（tools/ui-harness/）—— 渲染层快迭代用

**是什么**：用本机 Playwright 的 Chromium 直接打开 `app/src/main/assets/ui/index.html`，
注入一个**假原生桥**（实现 `pref.* / host.* / session.* / hermes.*` 这些 op），
于是不用起模拟器、不用连 SSH，就能把 WebView 的 JS/CSS/DOM 跑起来并**读回真实数值**。

```
node tools/ui-harness/harness.mjs t-fontsize.mjs     # 字号：生效 + 重载保持
node tools/ui-harness/harness.mjs t-settings.mjs     # 字号/回滚上限/开关：生效 + 回读 + 重载保持
node tools/ui-harness/harness.mjs d-debug.mjs        # 面板/传输层状态自检（排障用）
```

- 驱动文件默认导出 `{ name, boot?, set?, afterReload? }`：
  `boot` 先跑（看初始值），`set` 跑完**自动 reload 一次页面**，再跑 `afterReload`（验「存不存得住」）。
- `localStorage['__stub_prefs']` 就是假桥的「落盘」，重载后仍然在 —— 与原生 `Store` 的语义一致。
- 浏览器：`/vol1/1000/aicache/cache/ms-playwright/chromium-1234`（本地，不联网）。

**它不能替代什么**（说清楚，别拿它当验收）：

- 本地 Chromium 与 Android WebView 的**字体度量不同**（Roboto/Noto vs 本机字体），
  「多少列」这类数字**不能跨环境比**；能比的是「设置生效了没有 / 存住了没有 / 重载后还在不在」。
- 真手指路径（`adb shell input tap`）、真实冷启动（force-stop 后重开）、系统键盘、
  通知与后台行为，都必须在**模拟器上的 debug 构件**里另跑一遍。

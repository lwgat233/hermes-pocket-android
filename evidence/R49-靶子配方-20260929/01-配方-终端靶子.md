R-49 第 3 步 · 终端页「靶子」配方（2026-09-29）
=========================================================================
## 0. 为什么之前那次读数是"退化读数"（scrollHeight 561 = clientHeight 561）
终端里当时**没有超过一屏的内容** ⇒ `.xterm-viewport` 没有滚动空间，`离底 = scrollHeight - clientHeight - scrollTop` 恒为 0，
**判不出"到不到底"**。要判 R-49，先得让终端里有 >1 屏内容。

## 1. 为什么"把靶子写进启动命令"不生效（R49#2 报的：badge=TUI·鼠标、startCmd 没生效）
- 会话启动流程在 `app/src/main/assets/ui/sessions.js:104-116`：**先 `tmux.list` 读远端会话；只要列表非空就直接 attach**
  （`pick()`：用户点过的 `sel` 优先，否则 `list[0]`）——**`startCmd` 一行都不会执行**；只有"远端一个 tmux 会话都没有"时才发 `startCmd`，
  再否则才 `create()`（`tmux new -As hermes 'hermes --tui'`）。
- 宿主上**一直有 `hermes` 会话**（Hermes 自己就跑在里面）⇒ 永远走 attach ⇒ **"没有 tmux 会话"这个前提在本机不可能成立**（除非关掉 hermes，那会打断本人）。
- 顶栏 badge 的来源：`ui/app.js:1335-1342`，`badge = watcher.describe() + 聊天状态`，它描述的是**当前屏幕模式**。
  attach 到 `hermes --tui` ⇒ 备用屏 + 鼠标 ⇒ 显示 `TUI·鼠标`。**它不是"startCmd 生效"的标志。**
- ⇒ **正确的开关**：靶子**不要**写进 startCmd；在**宿主机上**另起一个 tmux 会话跑靶子，然后在 App 的
  **「会话」板块点那一行 → 弹窗里点「切过去」**（`ui/panels.js:771-810`；这一下会把 `sel` 设成它并发 `tmux attach -t 'hptarget'`）。

## 2. 靶子（脚本已在仓库里；宿主上一条命令挂起来，幂等）
- 脚本：`source/hermes-pocket/tools/target-lines.sh`
- 用法：`bash tools/target-lines.sh [首发行数] [之后每隔几秒追加] [追加次数]`
  · `bash tools/target-lines.sh` ⇒ 打 300 行就停
  · `bash tools/target-lines.sh 300 5 240` ⇒ 300 行后每 5 秒再打 1 行、共 240 次（量"封底跟随 / 上翻不被拽回"）
- 挂成常驻会话（**只删自己这个名字，不动别人的会话**）：
```
tmux kill-session -t hptarget 2>/dev/null
tmux new-session -d -s hptarget "bash __SCRIPT__ 300 5 240; exec bash"
```
- **我跑过的现测**：`tmux capture-pane -p -t hptarget -S -` ⇒ **300 行**、**300 行都带 `终端靶子-`**；
  会话窗口 24×80 ⇒ 内容比一屏多 **276 行**；末行 `终端靶子-300 … 行号=300`。

## 3. 识别标志（怎么确认"跑的是靶子"）
- 终端里出现 **`终端靶子-001 时间戳 行号=1`** 这种行（App 自带的 TUI 不会有这种字样）；
- 顶栏 badge **不再是 `TUI·鼠标`**（靶子是普通 shell，没有备用屏/鼠标）—— badge 只当辅助，
  **以"终端里有没有 `终端靶子-`"为准**；
- 宿主侧交叉核对：`tmux capture-pane -p -t hptarget -S - | grep -c "终端靶子-"`（应为 300）。

## 4. 设备上量什么（选择器 / 字段 / 公式）
- 滚动容器：`document.querySelector('.xterm-viewport')`（xterm 自己的视口）
- 字段：`scrollHeight`（总高）、`clientHeight`（可视高）、`scrollTop`（当前偏移）
- 判据：**`离底 = scrollHeight - clientHeight - scrollTop`**（0 = 贴底）
- 先决：**`scrollHeight > clientHeight`** 才算"有滚动空间"，否则读数是退化的
- 我这边同一条渲染路径的测试台读数（喂 300 行）：`scrollHeight 6367 / clientHeight 643 / 滚出 5724px / 离底 0 / 行高约 19.08px`（探针 `tools/ui-harness/t-r49-target-300.mjs`，报错 0 条）
